# CLAUDE.md

Context for Claude Code working in this repository.

## What this is

A working proof of concept for **Bahrain Tender Board tender 3/2026/SIO (PA Ref 07-2026)** —
"Chat Bot Solution" for the Social Insurance Organization, Kingdom of Bahrain.
Built by Nanta Tech to demonstrate the mandatory scope to SIO before the 23 August 2026 closing date.

It is a demo, not the delivery build. It exists to be shown on a laptop or projector and to prove
each mandatory requirement is real rather than described in a slide.

## Architecture

Deliberately dependency-free so it runs anywhere with Node 18+ and no install step.

```
server.js          Node http server. Serves public/ and proxies POST /api/chat
                   to the Anthropic Messages API with the key from .env.
                   The browser never holds a key. POST /api/tts returns free MP3
                   speech (unofficial Google Translate voice) for languages the
                   browser has no installed voice for. Speech input uses browser
                   SpeechRecognition, or in-page Whisper (transformers.js) where
                   that is missing, e.g. Firefox.
public/index.html  Markup: top bar, left nav, four views, right coverage rail.
public/styles.css  All styling. CSS custom properties at :root.
public/app.js      All behaviour. No framework, no build step, no bundler.
```

State persists in `localStorage` under `sio_kb_v2`, `sio_logs_v2`, `sio_state_v2`.

## How the assistant works

`systemPrompt()` in `app.js` builds the system prompt fresh on every turn from the current
knowledge base articles and rule set, so an edit in the admin view takes effect on the next
question. The model must return **strict JSON**:

```json
{ "reply": "", "lang": "en", "intent": "", "confidence": 0.0,
  "escalate": false, "handoff_reason": "", "tool": null, "suggestions": [] }
```

`parseJSON()` strips fences and slices between the first `{` and last `}`.

Two rules that must not be relaxed:

1. **The model never produces a benefit figure.** It returns
   `tool: {"name":"estimate_pension","args":{"wage":n,"years":n}}` and `estimate()` in `app.js`
   computes the amount from the editable rule set. Keeping arithmetic out of the model is a
   deliberate design position for a government social-insurance client — do not "simplify" it
   by letting the model calculate.
2. **Answers are grounded only in the knowledge base.** Anything uncovered sets `escalate: true`
   and produces a handoff ticket rather than a guess.

## The coverage rail

The right-hand rail maps 1:1 to the eight mandatory bullets in the tender notice. Each entry ticks
when the user exercises it — `mark('conv' | 'calc' | 'voice' | 'lang' | 'omni' | 'kb' | 'esc' | 'log')`.
This is the demo's spine: it turns the walkthrough into a compliance checklist. If you add a
capability, add its rail entry and its `mark()` call.

## Known placeholders

- `SEED_RULES` (2% accrual, 80% cap, 20-year minimum service, age 60, 8%/15% contributions) are
  **illustrative demo values**, labelled as such in the UI. Replace with figures from SIO's
  published regulations before any client demo.
- `SEED_KB` article text is generic procedural guidance, not quoted SIO policy.
- Sample conversation history is generated by `seedLogs()` so the dashboard is not empty on stage.
  Rows carry `sample: true` and are tagged in the log table.

## Out of scope here

SSO and core-system integration, production security hardening, hosting, and Bahrainisation
compliance belong in the technical bid, not this POC. The rail says so explicitly.

## Conventions

- Vanilla JS, 2-space indent, no framework.
- Copy is sentence case, active voice, no exclamation marks. Errors say what happened and what
  to do next.
- Arabic and Urdu render RTL via `dir` on the message bubble — check both when touching chat layout.
- Keep it responsive to mobile and keep visible focus states.
